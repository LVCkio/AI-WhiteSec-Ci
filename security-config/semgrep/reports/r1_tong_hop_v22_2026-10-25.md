## 2. Nhận xét

1. **Tầng high gần như chỉ có HARDCODED_CREDENTIALS.** Recall high của 5 lớp còn lại ≤ 0,07, trừ XSS Python (0,32) và OS_COMMAND Python (0,33). Rule taint hiếm khi báo: mẫu là một hàm cắt ra, source (request, tham số HTTP) thường nằm ngoài hàm. Recall chủ yếu đến từ rule audit.
2. **Ô yếu nhất trên train (n ≥ 20):**
   - INSECURE_AUTHENTICATION cả 4 ngôn ngữ: 0,00–0,06 (256 mẫu). Phần lớn là lỗi logic, đúng như giới hạn đã ghi ở semgrep_tool.md mục 4.
   - PHP PATH_TRAVERSAL: 0/23.
   - Java XSS: 0,04 (113 mẫu).
   - PHP HARDCODED_CREDENTIALS: 0,10; PHP XSS 0,18; PHP OS_COMMAND 0,20.
   - Số FN lớn nhất: XSS PHP 418, XSS JS 387, SQLi PHP 335, Auth Java 114, XSS Java 109, Hardcoded Java 106, Path Java 95.
3. **Báo nhầm trên mẫu âm cao ở tầng audit (≈ 20%).** Một số rule audit báo trên mẫu âm nhiều hơn trên mẫu dương: `team.php.audit.sql-api` 236 mẫu âm / 199 mẫu dương, `team.php.audit.echo-unescaped` 175 / 100, `team.php.xss-html-concat` 156 / 93. TC4 chỉ đo tỉ lệ đúng lớp trên mẫu dương nên không thấy điều này. Tầng high giữ được 2%.

## 3. Đề xuất cho R2 (chờ leader duyệt, chưa làm)

- Hạ `team.php.sqli-taint` xuống audit; với `team.php.xss-taint` rà tay ~10 ca báo sai trên **train v2.2** trước (nghi thiếu sanitizer), rồi mới quyết.
- 4 rule audit rớt trên train: xem lại pattern; nếu vẫn rớt thì chuyển vào `rules_disabled/`.
- Đặt ngưỡng tỉ lệ báo nhầm trên mẫu âm cho tầng audit (hiện là câu hỏi mở), vì đây là điểm yếu lớn nhất của tầng audit.
- R4 ưu tiên theo số FN train: XSS PHP/JS, SQLi PHP, Java XSS/Path/Hardcoded. Auth để CodeBERT xử lý.
